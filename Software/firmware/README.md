# 8HP TCU firmware (STM32F107VCT6)

Open-source transmission control for the ZF 8HP (first target: BMW GA8P75HZ
in EV conversions). Built on the openinverter libraries the same way as the
ZombieVerter VCU (Stm32-vcu): libopeninv parameters, terminal, CAN map and
SDO on top of libopencm3.

> **Status: first cut, not run on hardware.** It builds and the host unit
> tests pass, but nothing has been tried on Bob's board or a gearbox yet.
> The pins follow Bob's **Stm32_TCU_V4** rev C map (provisional, see "Pin map"), and several values
> that need a bench measurement are parameters with placeholder defaults
> (see "Parameters for unmeasured items" below). Do not connect this to a
> car until those are resolved.
>
> The firmware sends **no CAN frames** by default (`CanTxEnable = 0`,
> `LogEnable = 0`). SDO replies on CAN1 only go out when a tool asks.
> Immobiliser handling is out of scope.

The control strategy follows Ian's reverse-engineering notes of the F30
330e EGS (in the `8hp45-dump/analysis` package):
`330E_OPEN_TCU_CONTROL_SPEC.md`, `330E_SAS_FILL_RAMP.md`,
`330E_EDS_PWM.md`, `330E_MECHATRONIC_PINOUT.md`,
`330E_SHIFT_CLUTCH_FIRST_CUT.md` and the calibration export
`330e_cal_export/330e_sas_eds_cal.json`. Section numbers below (§) refer to
the control spec unless stated otherwise. [C] / [I] / [H] tags are Ian's:
confirmed in code / inferred / from public sources.

## Building

Ubuntu 22.04 or later:

```
sudo apt-get install gcc-arm-none-eabi g++ make git
git clone --recursive https://github.com/damienmaguire/8HP-TCU.git
cd 8HP-TCU/Software/firmware
make get-deps      # builds libopencm3 for STM32F1 (first time only)
make               # -> stm32_tcu, stm32_tcu.bin, stm32_tcu.hex (objects in obj/)
make Test          # host unit tests
test/test_tcu
```

If the repository was cloned without `--recursive`, run
`git submodule update --init` first (`make` does this for you if
libopencm3 has not been built).

Code::Blocks: open `tcu8hp.cbp`. The `STM32F107` target runs `make`, the
`Test` target runs `make Test`.

The image links at 0x08001000 (4 KiB bootloader in front, as on the
openinverter boards). Parameters live in the last 2 KiB flash page and the
CAN map in the page below it (libopeninv F1 layout, see `stm32_tcu.ld`).
Build output (`obj/`, `stm32_tcu*`) is ignored by git; no binaries are
committed. The CI workflow (`ci/CI-build.yml`, to be moved to
`.github/workflows/CI-build.yml` at the repository root to switch it on)
builds the firmware, runs the tests and attaches the .bin/.hex to the run.

  clutch pattern tables are byte-identical in every SH program [C]),
  except the F11 row's own line pressure, gear-in and stage 4 shift
  pressure above.

  follows the valve hardware revision, not the gearbox size. The F11 v058
  set equals the v095 8HP90 set for A..E and ch7 [C, checked by the
  generator]; **SYS differs**, so both are kept.
* Size data (torque class from `TAB_MVG_MT`, reverse limit start from
  `KL_RGANGLIMIT`, safety offset from `KL_MOMOTMAXNDRSS32`, plus the fill

time ms, torque Nm, speed rpm, temperature degC. Maps are stored
`z[iy * nx + ix]` with x = the first A2L axis. "Time before sync" cals stay
negative as in the ROM (-30 = 30 ms before sync).

## Architecture

```
            CAN1 (VCU)          speed sensors      ATF / Vbat ADC
                 |                    |                  |
                 v                    v                  v
 stm32_tcu.cpp   ----------- inputs every 10 ms ------------
                                      |
                                      v
 tcu.cpp       mode machine: INIT / PARK / NEUTRAL / ENGAGE / DRIVE / SHIFT / SAFE
               gear choice, line pressure, fault latch, torque-intervention ramp
                 |                 |                |
           engage.cpp          sas.cpp        interlock.cpp
           N->1, N->R          single-swap     max 3 applied (4 in a swap),
                               KZU/KAB phases  only the allowed elements
                 \_________________|________________/
                                   v
                    pressure per element A..E + line (mbar)
                                   |
 eds.cpp        KL_EDSKV* curves, temperature correction, slew 60 mA/10 ms,
                125 Hz dither (1 ms task)  -> current per valve (0.1 mA)
                                   |
 valveout.cpp   valve -> MAX22200 channel map (parameters), fault aggregation
                                   |
 max22200.cpp   SPI driver: HOLD DAC per channel (CDR), ON bits, faults
```

* **Integer maths only.** All lookups are clamped linear (curves) or
  bilinear (maps) interpolation with 64-bit intermediates
  (`src/caltypes.cpp`).
* **Hardware-free core.** Everything from `tcu.cpp` down to `max22200.cpp`
  has no libopencm3 or parameter dependency, so the same code runs in the
  host tests. `stm32_tcu.cpp` copies parameters into config structs and
  wires up the hardware.
* **Tasks** (Stm32Scheduler on TIM4): 1 ms dither + SPI updates + LIN
  schedule, 10 ms shifter + control + CAN, 100 ms faults, ATF, battery
  voltage. Interrupts: speed sensors (DMA half / full buffer at
  2.4 kHz), UART4 for LIN.

There is no Sol1 valve and no high-side supply switch.

**GP outputs** go through the valve driver (`valveout.*` aux outputs),
so they are **off whenever the valves are off**: safe state, driver
init failure or a valve map error. `ValveOut::Validate` refuses a valve
`Chx` on IC4 OUT1..3. `gpFault` shows a fault flag per GP output (bit 0
OUT1, 1 OUT2, 2 OUT3), `drvFlags1` the IC4 status.

**Speed sampling.** ADC1 converts IN0, IN1, IN2 back to back in
continuous scan mode (13.5 + 12.5 cycles at 12 MHz = 2.17 us per
conversion, 6.5 us per scan = **153.8 kS/s per input**; Bob asks
>= 100 kS/s, so 10 kHz at 10000 rpm x 60 ppr still gets 15 samples per
period). DMA1 channel 1 writes a circular buffer of 2 x 64 scans; the
half- and full-transfer interrupts (every 416 us, 2404 per second) hand
one half to `ScanEdges` (`speedsens.*`), which runs the `AdcEdge`
hysteresis edge test per channel and keeps the min / max levels.
The scan count is the time base (`SPEED_TIMER_HZ` = 153846). The slow
inputs are on ADC2 (`slowadc.*`, software-started every 10 ms, averaged
over about 4 readings; libopeninv `AnaIn` is not used); the die sensor
(ADC1 only) is one injected conversion every 100 ms, which pauses the
scan for 21 us.

DMA map (no clash): DMA1 CH1 = ADC1 (speed scan), CH2 / CH3 = USART3
terminal TX / RX. ADC2 has no DMA on the F1 (polled). SPI1 to the
MAX22200s is blocking (no DMA; its requests would be CH2 / CH3, taken by
the terminal, so it must stay that way). UART4 LIN is interrupt-driven
(its DMA would be DMA2 CH3 / CH5, unused). CAN has no DMA.

**CPU load (estimate from the disassembly, -Os).** The inner loop is
12 Thumb-2 instructions per sample, about 20-25 cycles with the flash
wait states: 461538 samples/s x 25 = 11.5 M cycles/s = **16 %** of
72 MHz. Per half buffer add the ISR entry / exit and set-up (~200
cycles, 0.7 %) and about 50 cycles per edge (two sensors at 10 kHz:
2.8 %), so **17 % with no signal, about 20 % worst case**; DMA bus
stealing adds about 1 %. The F107 copes:
the scheduler tasks need a fraction of what is left, and the ISR has the
scheduler's priority, so a 10 ms task can delay one half-buffer by at
most its own run time (the next half has 416 us to go). The ISR measures
itself: spot value `spdLoad` (0.1 %, DWT cycle counter, without entry /
exit), separate from `cpuload`. If the load is too high on the bench,
the sample time can go to 28.5 cycles (97.6 kS/s, 10 % less) or the
min / max levels can be taken on every 4th scan.

### Solenoid driver (MAX22200)

The valves are driven by MAX22200AETJ+T octal solenoid drivers over SPI
(data sheet Rev 1, 3/25; register, bit and figure numbers are cited in
`include/max22200.h`):

* Every valve channel runs in **current-drive regulation (CDR), low side**.
  The chip regulates the **peak** current of each chopping cycle
  (`I = HOLD / 127 x IFS`). There is no shunt and no software current loop.
* `IFS = 15 kV / RREF` (HFS = 0, up to 1 A). Both chips have RREF = 15k, so
  `MaxIfs` = 1000 mA. One HOLD step is then about 7.9 mA. HFS is per
  channel: `MaxHfsMask` bit n puts OUTn on half scale (500 mA, ~3.9 mA
  steps). Default 0 (no channel on half scale).
* The ceiling `IMaxCoil` (850 mA) caps every HOLD code. HOLD = 127 means
  "fully on, unregulated" (about 2.3 A into a 5 ohm coil) and is never
  written; the driver's largest code is 126.
* Start-up follows data sheet Figure 6: read STATUS (clears UVM), write
  STATUS with ACTIVE = 1 and all channels off, write the eight CFG_CHx
  registers, read STATUS again.
* A HOLD change is a one-byte write after an 8-bit command, sent only when
  the code changes. Channels switch with a one-byte write of STATUS[31:24].
* Faults (OCP, open load, HIT not reached, DPM, over-temperature, UVM,
  SPI error) are read every 100 ms and at once when nFAULT goes low, then
  cleared selectively (MAX22200A). A fault on A..E or SYS, a chip that
  reset itself (UVM) or a failed SPI echo puts the TCU in the safe state.
  Faults on K0 or POS are only reported.
* **Dither:** the MAX22200 has no dither generator, so the 125 Hz dither is
  made in firmware: the 1 ms task adds a triangle (or square) offset of
  `DitherAmp` (default 30 mA) with period `DitherPeriod` (default 8 ms) to
  the setpoint and rewrites the HOLD byte. At 7.9 mA per step a 30 mA
  dither is about +-4 codes. As in the OEM unit, dither is off near the
  50 mA and 850 mA end points.
* The command byte is built from data sheet Table 9 (address in bits 4:1).
  Analog Devices' no-OS driver puts the address in bits 6:0 instead. This
  firmware follows the data sheet; check it on the bench with a logic
  analyser before trusting it.
* Two chips (IC2, IC4), one chip select each, channels switched over SPI
  (IC2 TRIGA/TRIGB held low, IC4's tied to GND).

### Safe state / limp

All coils at 0 A gives C+D+E applied = **6th gear** mechanically, and line
pressure at maximum (SYS is normally high) [C]. On any critical fault the
TCU drops every output at once (no slew), disables the MAX22200 channels
and reports gear 6. Faults latch. `FaultClear = 1` is accepted only at
standstill in P or N; it restarts the drivers and leaves the safe state if
the cause has gone.

**Bench note, clutch B:** only B is pushed open by oil pressure; A, C, D
and E are returned by springs (BMW TIS). With the motor and pump stopped
B can stay closed even with its valve at 0 A, so on the bench do not take
"B valve vented" as "B open" without line pressure. The firmware never
does: gear-in waits for a pressure source, N keeps B pre-filled, and while
driving there is always line pressure. Shifts overlap: the releasing
clutch is held at a low pressure until the on-coming one carries the
torque (KAB hold / shift-pressure phases), so 4 clutches are briefly
applied in a shift, never 5; in a gear exactly 3. On upshifts the
off-going clutch is kept at least at its own fill pressure (`KL_PFCG`)
while the on-coming one is still filling: the OEM `KF_PKAB` target and
the `KL_PGOMTKAB` gradient can reach 0 bar before that, which would drop
the drive for a moment.

Critical faults: driver fault on A..SYS, chip lost, interlock rejection,
battery below `UvLimit` (OEM 7.4 V), input/output speed ratio not matching
the engaged gear for `GearChkMs`, invalid valve map.

### CAN

What runs on CAN1 is chosen by `EcuType` (`canif.cpp`, one handler row per
type: receive IDs, decode, frames to send). Only `0 = None/VCU` exists:
the placeholder VCU frames below. OEM engine ECUs (DME/DDE) will be added
later as more rows; no OEM ECU frames are in the firmware yet.

CAN1 (vehicle/VCU) and CAN2 (ZombieVerter link and logging, on by
default with `Can2Enable` = 1) both at 500 kbit/s by default. All
frame layouts below are **placeholders** until the VCU/inverter side is
agreed (Q5). Values little endian.

* RX `CanCmdId` (default 0x300): byte 0 selector (0=P 1=R 2=N 3=D, used
  when `ShifterType = CAN`), byte 1 gear request (0 = hold, 1..8, used
  when `ShiftMode = VCU`), bytes 2-3 actual motor torque Nm (signed),
  bytes 4-5 motor rpm (signed), byte 6 (optional) bit 0 tip up, bit 1
  tip down (both only with `ShifterType = CAN`), bit 2 footbrake pressed
  (needed to release park with `ParkBrake = VcuCan`; a 6-byte frame reads
  as not pressed).
  If it stops for `CanTimeout` ms the TCU posts `CANTIMEOUT`, uses
  `CanLossTq` for line pressure (default 600 Nm, the OEM substitute
  `D_m_IstVM_Default`) and follows `CanLossMode`: 1 (default, Damien's
  decision 2026-11-23) holds the gear at `LineMax`, refuses upshifts and
  only steps down as the car slows; 0 goes to neutral. Neutral/limp is
  kept for hydraulic and electrical faults (the safe state). No gear-in is
  started while the frame is missing.
* TX `CanStatId` (default 0x301, only if `CanTxEnable = 1`): gear, mode,
  target gear, fault, torque intervention request Nm (signed;
  `TqNoRedVal`, default 0, when there is none), ATF + 40,
  flags (bit 0 shifting, 1 park request, 2 safe state, 3 hold motor
  torque near 0 for gear-in, 4 CAN-loss gear hold, 5 coast shift). The torque intervention
  request is the hook for the inverter: how it reaches the inverter is
  open (Q5).
* TX `CanStatId + 1` (same condition): bytes 0-1 minimum motor speed the
  TCU asks for (rpm, 0 = none: 700 rpm to leave P and for 2 s after, or
  `PumpFaultRpm` with `PumpFaultAct = MotorSpeed`; the VCU should turn the
  motor with the clutches open), byte 2 bit 0 waiting to leave P, bit 1
  gear-in waiting for a pressure source, bit 2 Auto tip override, byte 3
  LIN pump fault classes, bytes 4-5 channel 7 pressure (mbar).
* TX 0x0B0, engine torque intervention (`RQ_TORQ_CRSH_GRB`), on **every
  row** (330e and F11 packers have the same shape [C],
  `F11_SAM_ADDSCOPE.md` 3). Only with `F11TqTx = 1` and `CanTxEnable = 1`
  (both off by default; the name `F11TqTx` is historical). 10 ms, DLC 8,
  Intel bits, torque scale Nm = raw x 0.5 - 1023.5 [C], 0xFFF = no value:
  byte 0 CRC-8 (poly 0x1D, init 0, no XOR) over Data ID 0x0001 (lo, hi) +
  bytes 1-7; byte 1 low nibble alive counter 0..14; bits 12-23 slow-path
  ("by air") request `sv_m_EngTqCtrlReqPred`, **0xFFF** (not modelled);
  **bits 24-35 absolute target** (`sv_m_EngTqCtrlReq`), 0xFFF = no
  request; bits 36-47 gearbox absorbing torque `sv_m_Gearbox`, **0xFFF**
  (not modelled); **bits 48-51 qualifier 0 none, 1 increasing,
  2 decreasing**; bits 52-63 target engine sync speed (x2.5 rpm), 0xFFF
  as the F11 sends. Idle bytes 2-7 = `FF FF FF FF F0 FF` (the logged F11
  idle had 0x7FF in bits 36-47; we have no value, so 0xFFF). The target is
  absolute: input torque `m_t` + the TCU's `tqDelta`; the sign of
  `tqDelta` picks the qualifier (`tq0B0`, `tqQual` spot values).
* TX 0x0A0 (`RQ_TORQ_CRSH_GRB_2`), optional, **off by default**
  (`TqCeilTx = 1` and `CanTxEnable = 1`): same E2E with Data ID 0x00A0,
  bits 32-43 = max allowed engine torque `sv_m_EngTqMax` (ceiling), same
  scale [C]; every other bit 1. `TqCeilNm` (0 = the row's torque class
  [I]; the F11 logs show 444 Nm in 3rd-8th).
* CAN gear levers: see "CAN gear levers" below.
* CAN2 log (only if `LogEnable = 1`), every 10 ms from `LogBaseId`
  (default 0x5F0): +0 pA pB pC pD, +1 pE pSys n_t n_ab, +2 iA iB iC iD (mA),
  +3 iE iSYS iK0 iPOS, +4 mode gear target zKZU zKAB engPhase interlock
  fault, +5 m_t tqDelta tSyn gls. The state numbers match the OEM ones so
  logs can be compared.
* libopeninv CAN map and SDO (node `SdoNodeId`, default 22) on CAN1, so
  any value can also be mapped from the web interface.

### CAN gear levers

`ShifterType` picks the lever; every lever goes through one lever-state
interface (P / R / N / D / M plus M+ / M- tips, `canlever.h`) into the
normal selector input, so the gear-in rules, the interlock and the
CAN-loss rules are the same for all of them. The lever only *asks*: a
change into R, D or P is taken only at or below `EngageMaxRpm` output
speed and with no TCU fault; a refused request flashes the display. N is
always allowed. When the lever's frames stop for longer than its timeout,
`CanLossMode` applies (hold the last position, or N). `LeverBus` picks
CAN1 or CAN2. All lever TX needs `LeverTxEnable = 1` **and**
`CanTxEnable = 1` (both off by default).

| Id | Lever | RX | TX | Timeout | Source |
|---|---|---|---|---|---|
| 0 | BMW GWS F30 / F11 | 0x197 DLC 4: CRC8(B1..B3) ^ 0x53 (E2E Data ID 0x003F), counter B1 low nibble 0..14 (one repeat tolerated, a second or a jump > 2 rejects, as the LIN pump), B2 high nibble = move (masked with 0xF0: the F11 low nibble is 0xF, the F30's 0xE), B3 P button (all three copies must agree) | 0x3FD DLC 5 every 100 ms: CRC8(B1..B4) ^ 0x70, counter 0..14, B2 0x20 P / 0x40 R / 0x60 N / 0x80 D, 0x08 flash [I], M sub-field `LeverMSub` [H]; B3 / B4 `LeverB34` (OEM FC FF, or ZV 00 + gear); 0x00 before KL15 and from KL15 off + 30 s | 90 ms [C] | egs_gws_lever_can.md, ZV F30_Lever.cpp |
| 2 | BMW E65 | 0x192, the ZV 24-bit patterns (P button, R+, D+) | none (ZV sends none) | 500 ms [I] | ZV E65_Lever.cpp |
| 3 | JLR rotary knob gen 1 | 0x312, B3 high nibble = knob position | 0x3F3 every 20 ms, ZV bytes and counter (skips 2-3 in P); stops 2 s after KL15 off | 500 ms [I] | ZV JLR_G1.cpp |

The GWS state machine (the lever reports moves, the TCU keeps the
position, as the OEM `D_Tab_RelToAbsConversion` does): a move counts once
it is seen in `LeverDeb` (2) frames in a row, once per move. Up1: P / D /
M -> N; Up2: -> R; Down1: P / R -> N; Down2: P / N / R -> D; side gate
(code 7, or 5 / 6): D -> M, back to the centre -> D; M+ / M- = one tip
up / down; P button -> P. Checked against the F11 capture `r10md10m`
(P -Up1-> N -Up2-> R -Down2-> D, P button -> P; a one-frame Down1 on the
way to Down2 is not taken, as the EGS did). In M the TCU gets tips; they
act as any tip does (Manual mode, or Auto with `TipOverride`).

Ported from Damien Maguire's ZombieVerter VCU (`Stm32-vcu`, branch
`BMW-F11-Dev`, `src/shifters/`, GPL v3), credited in `canlever.cpp`.
Not ported: the PKP2300 regen / heater toggles and state-of-charge bar
(VCU features), the ZV "no shifter" entry (= `VCU_Frame` here). The ZV
`opmode == !MOD_RUN` test in the JLR classes compares with 0; the port
does what it means (park display when not running).

**Only one node may own a lever's TX id** (0x3FD, 0x3F3, 0x02C, 0x215).
Do not enable `LeverTxEnable` on a bus with a live EGS, a ZombieVerter
running its shifter class (e.g. `F30_Lever`), or the DDE / EGS emulator:
two senders mean counter and CRC clashes on the lever display. 0x202
(BMW backlight / dimming) is never sent: it belongs to the body side.

`CmdSource = Param` takes the selector, gear, torque and motor speed from
the `SelectorSet`, `GearSet`, `TorqueSet` and `MotorRpmSet` parameters for
bench work without a VCU.

## Torque input, adaptation, diagnosis, lock-up, status stream

These five features are off or neutral by default: with default
parameters the TCU behaves as before.

### Torque input (`torquein.*`)

1. The torque the VCU / engine ECU sends in the command frame (default).
2. If that value is a "not available" code (0x8000 or 0x7FFF, how ECUs
   mark a missing signal) or frozen (below), and `TqModel` is on: the
   model. Placeholder table of Nm against engine speed and manifold
   pressure for a 300 Nm engine, scaled by `TqModelScale` (%); above
   100 kPa the 100 kPa value is multiplied by MAP / 100 and by
   `TqBoostPct` (%). MAP comes from `MapKpa` for now (no MAP input).
3. Otherwise the safe substitute `CanLossTq` (600 Nm: high torque = high
   clamping pressure). On a full CAN loss it is always `CanLossTq`.

`tqSrc` shows which (0 CAN, 1 model, 2 substitute, 3 bench parameter),
`tqUsed` the Nm used. `TqNoRedVal` is sent in status bytes 4-5 instead
of 0 when the TCU asks for no torque change (for ECUs that want a code).
`PedalPct` is the pedal used by the TCC schedule and the adaptation gate;
-1 (default) estimates it from torque / gearbox torque class, because
the VCU frame has no pedal.

Frozen signal: the torque has not changed by a single Nm for `FrzTime`
(3 s) while the engine speed moved more than `FrzRpm` (300 rpm). A real
torque signal always moves when the engine speed does. `FrzTime = 0`
switches the check off. Reaction: the substitute (or model), error
`TQFROZEN`. There is no live pedal signal yet, so the same check is not
fed with a pedal.

### Clutch adaptation (`adapt.*`, `AdaptEnable`, default off)

A learned fill-pressure offset per clutch **and** per oil-temperature
class, added to that clutch's calibrated fill pressure (KL_PFCG) when it
is the on-coming clutch, up- and downshifts.

* Classes [C, 330e A2L CS_UN/OB_ADAKALT / ADAWARM]: cold 10-30 degC,
  warm 50-110 degC. Between and outside them the nearer class is used
  (cold below 40 degC).
* Learning shifts: 3->4 learns D, 4->5 C, 5->6 E, 6->7 A, and the
  downshift 6->5 learns B (B is never the on-coming clutch of an upshift).
* Every entry condition is a parameter and must hold at the start and
  the end of the shift: torque `AdaTqMin`..`AdaTqMax` (55-180 Nm),
  engine speed `AdaRpmMin`..`AdaRpmMax` (1600-3200), oil
  `AdaOilMin`..`AdaOilMax` (55-80 degC) and inside a class, gears
  `AdaGearMin`..`AdaGearMax` (3-7), pedal above `AdaPedalMin` (2 %),
  driven at least `AdaDriveMin` (180 s) since power-up, `DriveMode`
  Normal without `ShiftMode` Manual, no TCU fault, torque from CAN.
  `adaStat` shows which conditions block (bit 0 disabled, 1 torque,
  2 rpm, 3 oil, 4 gear, 5 pedal, 6 drive time, 7 mode, 8 fault,
  9 outside a class).
* Rule (slow on purpose): input-speed flare above `AdaFlareRpm` or a
  shift longer than `AdaShiftMs + AdaBandMs` = filled late, +`AdaStep`
  (5 mbar); shorter than `AdaShiftMs - AdaBandMs` = harsh, -`AdaStep`.
  Limited to +-`AdaMax` (300 mbar). Target time and band are
  placeholders.
* Storage: its own flash page (`ADAPT_BLKNUM`, 0x0803E800), with magic,
  version and CRC-32. `save`, `load`, `defaults` and a parameter upload
  never touch it. Saved automatically when something changed and the
  car stands in P / N, or with the terminal command `adaptsave`.
  **`adaptreset` is the only way to clear it.** With `AdaptEnable` off the
  offsets are kept but not applied.
* Values: `adA_c`, `adA_w` .. `adE_w` (mbar), `adaShifts`.

### Fault detection (`diag.*`)

Classification only; the reactions are the existing limp / hold logic:

| Check | How | Reaction |
|---|---|---|
| Valve open | MAX22200 OLF | pressure valve: safe state (6th, full line pressure); K0 / POS / PZYL: reported |
| Valve short to battery | MAX22200 OCP | as above |
| Valve resistance high | MAX22200 HHF (hit current not reached) | as above |
| Valve short to ground / resistance out of band | V / I against 5.15 ohm at 20 degC [C, OutMRstn_resActr20_C], +0.393 %/degC, + `DiagRWire` (150 mOhm [C]), band `DiagRBand` (25 %) | as above, **only once a board has coil current read-back** (the board has none: not fed) |
| Paired channels | both channels of OUT0/1, 2/3, 4/5 or 6/7 faulted: shared supply / ground / harness | `diagPair` bits, plus the per-channel reaction |
| Speed sensor open / short | ADC level stuck above `DiagSpdOpen` / below `DiagSpdShort` with no edges (both 0 = off: input circuit levels not measured yet) | `ERR_SPEEDSENS`; the gear check (TF_SPEED) reacts |
| Speed sensor no signal | no edges while the other shaft turns faster than `DiagSpdNoSig` in a steady gear | as above |
| Lock-up slip | TCC closed but engine - turbine speed > `TccSlipMax` for `TccSlipMs` | TCC kept open, `ERR_TCCSLIP`, cleared with `FaultClear` |
| Frozen torque | see Torque input | substitute torque |
| CAN timeout per bus | VCU frame on CAN1 (`CanTimeout`), lever on its bus (`LeverTimeout`) | `CanLossMode`; `canBus` bit 0 / bit 1 |
| Firmware / calibration | `CalSigExp` (0 = off) against `CAL_SIG16`, a CRC-16 of the generated tables (`calSig` shows it) | configuration error at boot: nothing driven, `ERR_CALSIG` |

`dgA`..`dgPzyl`: 0 OK, 1 open, 2 short to battery, 3 short to ground,
4 resistance high, 5 resistance low. **TBD, not invented:** the slip and
pressure plausibility limits (the OEM monitors were not traced), so
`TccSlipMax` defaults to 0 = off and there is no pressure plausibility
check.

### TCC lock-up (`tcc.*`, `TccMode`)

`TccMode = Simple` (default) keeps the `TccOnRpm` / `TccOffRpm` rule.
`TccMode = Schedule`:

* Per gear, the input speed at which the clutch closes against pedal
  (0-100 %), placeholder table (later with more pedal, earlier in high
  gears). Opens `TccHyst` (200 rpm) below that, always open below
  `TccMinRpm` (1100), below `TccMinGear`, in a shift, gear-in, N / P / R
  and with a lock-up slip fault.
* Control: PI on slip (engine - turbine): `TccStartP` (1500 mbar) +
  `TccKp` x error + `TccKi` integral, limited to 0..`TccPress`. Target
  slip 0, or `TccSlipTgt` (default 0 = off) at or below `TccSlipGear`
  (3rd) and below `TccSlipRpm` (1800). Without an engine / motor speed
  the slip is unknown and it runs on the start pressure.
* The Sport / Track `TccOfsRpm` offsets only act on the Simple rule.

### Status stream (`statstream.*`, `StreamEnable`, default off)

Our own layout, little-endian, from `StreamBaseId` (1728 = 0x6C0) on
`StreamBus` (CAN1 needs `CanTxEnable` as well; CAN2 sends whenever it is
up):

| Id | Rate | Bytes |
|---|---|---|
| base+0 | 100 Hz | 0-1 torque target Nm (signed: input + intervention), 2 reduction % of input, 3 flags (bit 0 shift active, 1 coast, 2 intervention, 3 inertia phase, 4 TCC closed), 4-5 slip rpm (signed), 6 alive counter, 7 0 |
| base+1 | 100 Hz | 0-1 n_t, 2-3 n_ab, 4-5 engine / motor rpm, 6-7 n6 (0 when not fitted) |
| base+2 | 40 Hz (20 / 30 ms) | 0 gear (0 N, 1-8, 9 R), 1 target, 2 selector, 3 TCU mode, 4 lever state, 5 drive mode, 6 KZU state, 7 KAB state |
| base+3 | 20 Hz | 0 TCU fault, 1-2 valve fault bits, 3 ATF + 40 degC, 4 board + 40 degC, 5 battery 0.1 V, 6 adaptation status, 7 bit 0 CAN loss, 1 lever timeout, 2 torque not from CAN |

## Implemented vs stubbed

Implemented:

* Gear/clutch tables, single-swap table (tested against §5.1), interlock.
* SAS upshift and downshift phase machines with OEM state numbers, fill,
  ramps, GLS, sync detection, timeout, torque intervention and its ramp-out.
* Coast shifts (zug_schub_sas): picked at runtime from the sign of `m_t`
  at the start of the shift, using the negative-torque points of the same
  maps (there are no separate coast ROM sets). The GLS moves to the other
  clutch: KZU for power-on upshifts and coast downshifts, KAB for coast
  upshifts and power-on downshifts (`KP/KI_GLSKAB`, `KL_TVGLSKABCG`).
* N->1 / N->R engage with the last clutch per gearbox variant, neutral
  with B pre-filled.
* Line pressure: `max(KF_PSYS_<gear>(m_t, n_mot), P_SYSMIN<xy>)` while
  shifting, `P_SYSMIN_D/R` while engaging, `KF_PSYSN` in N/P, plus
  `LineOffset`, capped at `LineMax`.
* Pressure -> current with temperature correction, slew limit, firmware
  dither.
* MAX22200 driver, configurable valve map, fault handling, limp mode.
* Speed sensors (ADC1 + DMA scan with hysteresis), ATF resistance and
  table, battery voltage.
* Web-interface dropdowns: `GearboxType`, `ShifterType`, `ShiftMode`
  (see "Setup parameters").
* LIN aux oil pump master (UART4), off by default; see "LIN oil pump".
* CAN1 command/status placeholders, CAN2 logging, CAN map, SDO, terminal.
* `ShiftMode`: Auto (simple input-speed thresholds, default), Manual
  (driver tips with rpm limits and lugging protection, or the
  `ManualGear` dropdown), VCU (gear from the CAN frame). 12 V shift up /
  down inputs and Auto tip override (`TipOverride`).
* Variant rows (`GearboxType`, 7 rows) and `SolCurveSet` (see
  "Calibration tables"), gear-in last clutch per variant (F11 / v095: C
  for 1st, D for R; 330e: B with the A+C / A+D pre-fill), channel 7 mode
  (`Ch7Mode`; K0 on a row without K0 = open), LIN pump only on the 330e,
  0x0B0 torque frame on every row (TX off).
* Park lock sequence (Ian 11 Q9d / 12.1): leaving P waits for the motor
  at `ParkRelRpm` (700) or a measured 17 bar, asks the VCU for that speed
  and holds it `ParkRelHold` (2 s) after; P -> N `ParkPNDelay` (150 ms);
  N -> P 1000 / 500 / 300 / 150 ms at -30 / -15 / 0 / 40 degC (from a
  drive range `KL_TVPSEIN`); with `ParkCtrl = 1` PZYL at `PzylCurrent`
  (550 mA + cold offset up to 190 mA) while released and the park magnet
  for `ParkMagMin`..`ParkMagMax` (100 ms .. 1 s) after a release.
  `ParkCtrl` is 0 by default (outputs stay off) until the bench confirms
  the PZYL channel and the sequence.
* Park checks from the TIS cross-check (Ian, T.3 / T.4):
  * **Engage** (N -> P): only below `ParkEngKmh` (5 km/h, TIS) and with
    the output shaft below `ParkEngNab` (5 rpm, OEM `N_ABBRTVPSEIN`, the
    stricter one). km/h is worked out from the output speed with
    `NabPerKmh` (output rpm per km/h, default 25 [I]: set it from the
    axle ratio and tyre size). Until then the TCU stays in N (`parkInh`
    = 1) with PZYL still on; only then do PZYL and the magnet go off.
  * **Release** (P -> R / D / N): 17 bar stable for `ParkPNDelay`
    (150 ms) or the motor at `ParkRelRpm`, **and** the footbrake. The
    footbrake comes from `ParkBrake`: 0 = VCU frame byte 6 bit 2
    (default; lost with CAN), 1 = the `BrakeIn` parameter, 2 = bypass
    (bench only), 3 = the 12 V brake switch input on J1.46 / PD1 (for
    installs without CAN; debounced over 30 ms, active high). `brakePin`
    shows the input, `brake` the footbrake the TCU uses, and `parkBrkW`
    = 1 while it waits for the brake.
  * **Magnet**: at most 1 s per energise (`ParkMagMax` is capped at
    1000 ms, and the output itself is cut after 1 s, the `ParkHoldTest`
    bench test included). It is not used to hold N with the motor off:
    with no oil pressure the spring puts the lock in, which is the safe
    way round. TIS says the OEM magnet holds the piston in N with the
    engine stopped; that needs a hold current or pulsing we have not
    measured, so it is not supported.
  * **Auto-P** (engine off in drive; stopped in R/D with no pedal, belt
    off and door open, TIS) is **VCU logic**, not done in the TCU: the
    VCU sends P when it wants the lock in.
  * In the safe state every coil is off, PZYL included, whatever the
    speed: there the lock relies on the hydraulics (see "Safe state").
* Gear-in source rule (Ian 11 Q9d [I]): N -> D/R only after the LIN pump
  has delivered for `GearInPumpMs` (1 s) or with the motor at
  `GearInMotRpm` (100 rpm), and with line pressure at least `GearInMinP`
  (8 bar, `P_SYSMINIEP`; the OEM `P_SYSMIN_D/R` 9 bar is higher and
  wins). **Bench note:** with no pump and the motor at 0 rpm there is no
  gear-in (and no leaving P below 700 rpm); set `MotorRpmSet` with
  `CmdSource = Param`, or `GearInPumpMs = GearInMotRpm = 0` / `ParkRelRpm =
  0` to switch the waits off.
* Pump fault reaction `PumpFaultAct` (Ian 11 Q9a): 0 = report (default),
  1 = ask the VCU for `PumpFaultRpm` (600) in P/N with the clutches open,
  2 = no new gear-in while the fault is there.

Stubbed / not done yet:

* **Park lock outputs**: written (see above) but off by default
  (`ParkCtrl = 0`); PZYL is on IC4 OUT0 (`ChanPZYL = 8`);
  the magnet / PZYL order is [I].
* **Electric oil pump (IEP) over LIN**: done to Ian's OEM read (see "LIN
  oil pump"), but untested on the TJA1021.
* **n6 cross-check**: the third speed input is read
  (`nAux`). The 330e virtual-turbine factors `D_k_n6` / `D_k_nab` /
  `D_k_nmot` (+ `_ntOpt`) are now exported (`calN6`), but their index ->
  gear mapping is [H], so they are not used for control. The F11 has no
  such tables and uses its turbine sensor directly [C].
  Shifting uses n_t / n_ab with the ratio check (`GearChk*`) and the
  "never more than 3 applied clutches" interlock, as Ian suggests.
* **TCC lock-up (F11)**: a simple lock above `TccOnRpm` / open below

* **F11 POS / Sol1**: unconfirmed. No POSV / Sol1 / park constants in

* Skip shifts and the OEM routing tables (0x51418 / 0x51350): v1 only does

* `TAB_IKABENTLEER` (0x234c78), the shift-type switch for an off-going

### Drive modes

`DriveMode` (category "Drive Modes"). Normal is the calibration as it is.
Sport and Track use the **OEM Sport tables from Q030** (every `*SPORT*`
label for the shift and fill maps, Normal where a map has none; Track
uses the same Sport tables). On the F11 row, Sport and Track run the F11's
own shift programs 1 (SP) and 2 (SPORT) [I] for the shift maps (stage 4,
see Calibration tables) and the Q030 Sport set for fill. Both add
**parameter-driven modifiers**
(`drivemode.cpp`), so they stay tunable:

| Modifier | Sport | Track | Limits |
|---|---|---|---|
| Upshift speed | `SportUpOfs` +300 rpm on `AutoUpRpm` | at `TrackRedline` 5500 rpm only | never above `ManMaxRpm` |
| Downshift speed | `SportDnOfs` +200 rpm on `AutoDownRpm` | `TrackDnOfs` +400 rpm | kept 500 rpm below the up point |
| Shift time scale | `SportTime` 100 % | `TrackTime` 100 % | 50..100 %, quicker only (100 % now that the OEM Sport tables set the timing) |
| Earlier TCC lock-up | `SportTccOfs` -200 rpm on `TccOnRpm` / `TccOffRpm` | `TrackTccOfs` -300 rpm | only where ch 7 is TCC (F11) |
| No upshift on lift-off | - | Auto: no upshift at or below `TrackLiftNm` 10 Nm input torque | always upshifts at `ManMaxRpm` |

**All Sport / Track defaults are placeholders**: not measured, not OEM,
kept small on purpose. The time scale shortens the fill-equalise time, the
torque / KAB ramps and the KAB hold points referenced to the fill end
(`sas.cpp` `TScale`); it never touches the quick-fill pulse (clutch
volume), sync detection, T_SYN, the GLS delays or the shift timeout. The
interlock, line pressure, the gear-in rules, the tip rpm limits
(`ManMinRpm` / `ManMaxRpm`), the CAN-loss rules and every other safety
limit are not changed by any mode. The mode's up / down points do feed
the lugging step-down (also in Manual and in CAN-loss hold, which still
never upshifts). OEM Sport maps: `VariantCal::upMode` / `downMode` /
`clutchMode` point Sport and Track at `calUpSport` / `calDownSport` /
`calClutchSport` (F11 row: `calF11Up/Down[1]` and `[2]`). Note: Q030 `SP` in labels like `KF_TOSFHSSP_x` means
"spontaneous" and `SP31` etc. are skip shifts; neither is Sport.

**Start-up and flash checks.** The TCU uses the same flash pages as the
ZombieVerter. A board that last ran the ZombieVerter still holds its
parameters and CAN map, with valid CRCs, but those ids mean other things
here. So at start-up the TCU only loads the parameter page when every key
in it is one of its own parameter ids, and only then loads the CAN map.
Ids this firmware used before and has removed (`PARAM_RETIRED_IDS`,
for example the old ATF curve parameters 28-33 and 137-142) also count as
its own, so a page saved by an older build still loads; those entries are
skipped. Otherwise it starts on defaults (`paramSrc` = 2) and the page is left
untouched until `save`. Every loaded value is also checked against its
min / max; one outside goes back to its default.

If the hardware watchdog restarts the board, the next start blinks the
LED once per start-up stage the last start reached (200 ms on, 300 ms
off, then 1 s dark) before going on: 1 clocks / RTC, 2 pins, 3 speed ADC,
4 slow ADC, 5 parameter load, 6 adaptation load, 7 SPI / LIN UART,
8 applying parameters, 9 interrupts, 10 terminal / CAN1, 11 CAN2,
12 CAN map, 13 valve drivers, 14 scheduler, 15 running. The same number
is shown as `bootStage`.

Not available, so not added: **measured coil current** (the MAX22200 has
no current read-back, only the fault flags above) and the **pump
temperature in degC** (the OEM 0x33 curve, raw 12..199 -> 120..150 C, is
flagged odd by Ian; `lpTempRaw` stays raw). For `tBoard` the ADC1 sample
time went from 7.5 to 239.5 cycles (the sensor needs >= 17.1 us); the
slow scan of the other inputs is now 1.3 ms, still far inside the 100 ms
use.

### LIN oil pump

The driver follows Ian's read of the OEM driver, `330E_LIN_OIL_PUMP.md`
(330e `CDD_IEP_Control`), which replaces the guesses from Damien's bench
summary (no timed cold-start phases, no echo: byte 6 is a CRC). Labels are
Ian's [C]/[I]/[H].

What is implemented:

* 19200 baud, TCU master, 8-byte frames. Schedule 0x30, 0x32, 0x30, 0x33,
  0x30, 0x34 on `LinSlotMs` slots (10 ms [I]), so 0x30 every 20 ms. PIDs
  F0 / 32 / 73 / B4 [C].
* 0x30 [C]: b0 0xAA off / 0x55 run (0xCC / 0x33 unused); b1 flags (0x02
  clear errors for exactly one frame, at bus start and on `FaultClear`,
  then 400 ms without diagnosis; 0x04 limp and 0x08 warm-up defined but
  not requested yet); b2 oil temperature + 50; b3 after-run 0; b4-5 0; b6
  CRC-8 over b0 (poly 0x1D, init 0, no XOR: AA -> 73, 55 -> B7); b7 alive
  counter 0-15.
* 0x32 [C]: EB0/EB1, operating point, speed x 32 rpm, current 0.2 A/bit,
  voltage 0.1 V/bit (14.0 V until a valid frame), CRC-8 over b2, alive.
  0x33 (temperature raw, 32-bit ID) and 0x34 (HW / SW version, IEP85
  check) are decoded raw.
* Receive checks as the OEM [C]: LIN checksum; 0x32 CRC-8 (2 bad in a row
  = fault); alive counter repeated twice or jumping by more than 2 = fault,
  frame dropped; no valid 0x32 for `LinBusFault` (1.8 s) = bus fault. Fault
  classes use the OEM `ctl_IEP_Status` masks (EB0 0x40/0x80 = permanent
  level-2 safety fault, 0x10/0x20 = pump comms fault).
* Run rule (330e) [C values, I for how they combine]: input speed below
  `LinPumpRpm` 500 rpm (hysteresis `LinPumpHyst` 50), sump `LinTempMin` ..
  `LinTempMax` (0..125 degC), commanded line pressure below `LinPMax`
  (20 bar); keeps running `LinOffDelay` (800 ms, `D_t_IEP_ShutdownDelay`
  [I: use]) after the rule drops. `LinPumpP` (4 bar, `KF_PIEP_SYS`) is the
  pressure the OEM assumes from the pump; it is shown (`lpPress`) but not
  used by the line-pressure model yet.
* `GearboxType = F11`: the bus stays off (the F11 8HP45 has no LIN pump
  [C]). `LinPumpEnable` stays 0 by default.
* From Ian's section 11 (23 Nov 2026): 0xAA -> 0x55 directly, no settle
  phase [C]; status ignored for 1 s after the bus starts [I] and 400 ms
  after a clear [C]; "not delivering" armed `LinArmMs` (1000 ms,
  `KL_TVERZSYMIEP`) after the run command and set when the pump has
  reported less than `LinDelivRpm` until `LinSymMax` (1500 ms,
  `KL_TMAXSYMIEP`); on < 500 / off > 550 rpm, not above 20 bar, 0..125
  degC or down to -15 degC for 5 s at most; P does not switch it off;
  charging plug in -> LIN asleep (`ChgPlugSrc` = Param + `ChgPlugSet`
  for now; the input is TBD); no ECU limit on the pump voltage (it flags
  its own, EB1 bit 2), diagnosis blanked below `UvLimit` (7.4 V); alive
  counter low nibble only, starts at 0 at power-on, not reset when the
  bus restarts [C/I]; the 0x30 never depends on the replies, and
  `LinRxCheck = 0` stops the replies raising faults.

### Valves and speed sensors (Ian section 12) - bench items for Damien

* Valve map [I]: for an EV drop K0, leaving 8 proportional valves A..E,
  SYS, POS, PZYL. POS = position valve (switch-over 420 mA, `I_EDSPOSV`
  [C]). PZYL = park cylinder valve MvPZyl (550 mA `I_EDSPSV` + cold
  offset). The park magnet is the on/off NCV8402 on PC7 and is needed
  with PZYL.
* Ian (`F11_SAM_ADDSCOPE.md` 4): OEM Sol1 = VFS7 (`SrvShr_idxSol1_C = 7`)
  [C]; ch6 has the rising-valve class, so **ch6 = POS** [I]; SYS and
  MvPZyl are ch8 / ch9, order unknown [H]. Bob's "OUT6 = PREL -> POS" is
  refuted as a naming match: in the public pinout pin 6 "park release" is
  the park cylinder valve (PZYL), and Bob's map already gives PZYL its
  own channel, **IC4 OUT0 / J1.42**. So OUT6 / J1.3 drives POS only if
  the harness routes the POS valve there. The firmware keeps `ChanPOS = 6`
  and calls OUT6 "OUT6 (POS? bench-check)".
* **Bench item: ohm out J1.3 (OUT6) and J1.42 (PZYL, IC4 OUT0) to the
  mechatronic connector pins before driving either** [H]. Set `ChanPOS` /
  `ChanPZYL` from the result.
* OEM OUT7 = Sol1, on/off, 0.95 A peak / 0.4 A hold; identity unproven.
  Not used and not mapped. (This is the OEM ECU's OUT7, not IC2 OUT7.)
* F11: 7 proportional (A..E, SYS, TCC); the next item at 0x19FE14 is
  `KF_KIEDSCGFAACE`, not a POS curve. No K0, park, POS or Sol1 constants.
* Speed: n_ab, n_t and n6 on both gearboxes, 60 ppr, 30 rpm minimum (the
  `Teeth*` and `SpdMinRpm` defaults). n6 is a safety cross-check only.
* Open for the bench: channel -> pin -> valve map (drive one channel at a
  time), Sol1 identity, OEM OUT10 and OUT12-14, which connector input
  n6 is on.
